# Go Service Testing Conventions

How to test Go microservices scaffolded via `aoh-go-init`. `go.md` covers
writing the code; this file covers proving it correct. The patterns here are
extracted from worked AOH services — follow them so suites stay consistent
across projects.

## Test pyramid

| Layer | Lives in | Doubles | Runs via |
|-------|----------|---------|----------|
| Service unit | `internal/service/*_test.go` (`package <pkg>_test`) | mockery repo mocks + hand-written publisher/client fakes | `make test` |
| Handler | `internal/handler/*_test.go` (`package handler` — internal, see below) | hand-written service fakes + auth stand-in | `make test` |
| Upstream HTTP client | `internal/<client>/*_test.go` | `httptest.Server` fakes | `make test` |
| Repo / SQL | `internal/repo/*_integration_test.go` (`//go:build integration`) | real PostgreSQL via `<SVC>_TEST_DSN` env | `make test-integration` |
| E2E | the consuming web app's Playwright suite | live compose stack | manually, against composed-up infra |

`make test` regenerates mocks first (mockery) and must pass with no
infrastructure running. Integration tests are opt-in by build tag — never let
a default `go test ./...` depend on a database.

## Test doubles

- **Wide interfaces** (the entity repository, the entity service): mockery
  mocks, declared in `.mockery.yaml`, regenerated by `make mock`. Use
  `.EXPECT()` with `mock.MatchedBy` to assert structurally on the argument
  (status set, audit fields stamped, tenant propagated). Mockery fails the
  test on any unexpected call — exploit that: constructing a mock with **no**
  expectations is the assertion that the layer below is never reached
  (validation rejected the input first, tenant was empty, etc.).
- **Narrow interfaces** (≤ ~3 methods: event publishers, notification
  clients, stats repos): hand-written fakes in the test file. Add the
  one-line comment explaining the trade-off ("surface is small enough that
  mockery adds more cost than value") so the next contributor doesn't churn
  it back.
- Never maintain both a mockery mock and a hand-fake for the same interface.

## Naming, structure, assertions

Select cases by equivalence partitioning + boundary-value analysis (see
`references/project.md` → Testing) before naming them.

- `Test<Method>_<Scenario>` or `Test<Method>_<Scenario>_<Outcome>`, with the
  scenario wording mirroring the spec scenario the test proves —
  `TestUpdate_ReportedToAcknowledged_SetsAckTimestampAndPublishes`, not
  `TestUpdateOK2`. A failure should read as a broken requirement.
- Default to the external test package (`package service_test`) — test the
  exported contract. Drop to the internal package only when the test must
  reach unexported wiring (handler tests injecting typed context keys).
- **testify everywhere** — no raw `t.Errorf`/`t.Fatalf` assertion chains.
  `require` for preconditions and anything that makes later assertions
  meaningless (nil checks, decode errors); `assert` for the verifications.
- Fixed clocks: inject `now func() time.Time` (or pass `now` as a parameter)
  and pin `time.Date(...)` in tests. Assert window boundaries exactly
  (`[now-24h, now)`), not "roughly recent".

## Service-layer rules

Every entity's service tests cover, as a floor:

- **Classification** — each failure path asserts the returned
  `*aoherr.Error`'s `Class()` and `Code()` (via `errors.As`, or `errors.Is`
  against a sentinel — `Is` matches on class + code, ignoring message and
  cause), and validation failures assert the field name in `Details()`.
  Assert the *class*, not an HTTP status: the status is the renderer's.
- **Tenant isolation, both directions** — empty tenant →
  `aoherr.ClassAuthorization` *without touching the repo* (mock with no
  expectations); cross-tenant lookup → repo not-found sentinel →
  `aoherr.ClassNotFound`.
- **OCC** — stale `occ_lock` → the repo's conflict sentinel →
  `aoherr.ClassConflict`.
- **Repo sentinel translation** — the repo returns its own sentinels
  (`repo.ErrNotFound`, …); tests pin the service's translation so the
  one-way dependency rule stays load-bearing.

## Async side effects (fire-and-forget publishers)

Post-commit publishes run in goroutines. Capture them with a buffered channel
on the fake and a `select` with timeout — never `time.Sleep`:

```go
select {
case evt := <-fake.statusCh:
    assert.Equal(t, "acknowledged", evt.NewStatus)
case <-time.After(time.Second):
    t.Fatal("status_changed publish did not fire within 1s")
}
```

Negative assertions ("description-only update must NOT publish") are
mandatory wherever the spec says an event is conditional. Prefer ordering the
negative behind a synchronizing positive event (do the non-publishing call,
then a publishing one, then assert the channel yields only the second);
fall back to a short bounded wait (~100ms) only when no such sync point
exists. For polling conditions use `require.Eventually`, never sleep loops.

## Handler tests

Don't stand up Keycloak in unit tests — `aohhttp.BearerAuth` needs a live
JWKS endpoint. Instead, mirror the production route wiring with a stand-in
for the auth middleware that injects the typed context values, and keep the
**real** permission middleware in the chain:

```go
// package handler — internal: needs the unexported context keys + middleware.
func newXTestRouter(svc service.XService, tenant string, perms []string) http.Handler {
    r := chi.NewRouter()
    r.Use(func(next http.Handler) http.Handler {
        return http.HandlerFunc(func(w http.ResponseWriter, req *http.Request) {
            ctx := req.Context()
            if tenant != "" {
                ctx = context.WithValue(ctx, tenantID, tenant)
            }
            ctx = context.WithValue(ctx, tenantPermissions, perms)
            next.ServeHTTP(w, req.WithContext(ctx))
        })
    })
    h := xHandler{svc: svc, now: func() time.Time { return time.Date(/* fixed */) }}
    r.With(requirePermission(permXRead)).Get("/...", h.get) // same wiring as production
    return r
}
```

Assert per route, with `httptest.NewRecorder` and a decoded `map[string]any`:

- **200** — status, envelope shape (`data` present, `sent_at` present), and
  the `data` payload fields.
- **401** — no tenant in context → the handler's own guard, and the body is a
  conformant error carrying the shared authentication `errorCode`.
- **403** — permission missing → the real `requirePermission` rejects before
  the handler; also one case where the *service* returns an
  authorization-class error.
- **400** — one validation path proving the class → 400 derivation, and that
  `details` is an array of objects naming the offending field. Don't re-test
  every service validation at the handler layer — that contract is already
  pinned in the service tests.
- **500** — one path where the service returns an *unclassified* error,
  asserting the body is conformant and contains none of the underlying text.
  Suppression is the renderer's property; this test is what proves the handler
  did not defeat it.

Error-body assertions belong to the error contract, not to this file — see the
`aoh-error-handling` skill for the keys and their formats.

## Upstream HTTP client tests

Clients for AOH services (RTUS, UNH, DASH, …) are tested against
`httptest.Server` fakes. Assert the wire contract: method, path, auth
header, body shape.

**Pin the error contract explicitly — it is the point of these tests:**

| Client kind | Upstream 5xx | Connection refused | Empty config (disabled) |
|---|---|---|---|
| Fire-and-forget (publish, notify) | `nil` (warn-logged) | `nil` | `nil`, and **no HTTP call** |
| Must-succeed (admin/config setup) | error | error | error |

Test every cell that applies. The "no HTTP call" cases use a `called` flag on
the fake handler.

**Idempotent seeders/reconcilers** get an in-memory fake of the upstream
surface with per-method call counters and an OCC check on PATCH. The minimum
suite: cold start creates everything (count the POSTs); a warm re-run POSTs
nothing and converges; a third run still converges after occ_locks advanced;
the warm PATCH echoes the *current* occ_lock and omits fields the user may
have customised; unreachable upstream surfaces an error for the caller to
warn-log.

## Repo / SQL integration tests

Gated by `//go:build integration` **and** an env-var skip, self-migrating,
with a copy-paste usage comment at the top of the file:

```go
//go:build integration

// Runs against a real PostgreSQL from `<SVC>_TEST_DSN`; skipped when unset.
//
//   <SVC>_TEST_DSN='postgres://...' go test -tags=integration ./internal/repo/...
```

Use a unique tenant per run (`"test-tenant-" + timestamp`) for isolation
instead of truncating tables. Expose the invocation as a `make
test-integration` target — a DSN recipe that lives only in a comment doesn't
get run.

**What MUST be integration-tested, not mocked:** SQL aggregations (`GROUP
BY` counts, `AVG` with `NULL`-on-empty semantics), OCC `UPDATE … WHERE
occ_lock = $n` row-count behaviour, sort/pagination SQL, and any query whose
plan is supposed to use a specific index. A mockery-based unit test of these
proves only that the mock returns what you told it to.

## What NOT to test

- Log output or log levels — assert behaviour, not telemetry.
- swag annotations, struct tags, generated mocks.
- The bearer-auth middleware against live Keycloak — the consuming web app's
  E2E suite covers the real token path.
- The same validation rule at both handler and service layers — pin it once
  at the service, prove the translation once at the handler.
